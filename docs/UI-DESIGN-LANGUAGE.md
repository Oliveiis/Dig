# Dig UI 设计语言规范

> 版本：v1.2  
> 更新日期：2026-08-10  
> 适用范围：港岛 MVP 的漫游、搜索、日志、设置与所有店铺内容组件  
> 界面语言：繁体中文（香港）

## 1. 设计目标

Dig 的界面要让用户在陌生街区里更快做决定，而不是把更多地图信息塞进一个屏幕。

设计应同时满足四个感受：

1. **清醒**：地图和内容层级明确，不用装饰制造热闹。
2. **明快通透**：以冷白、浅青灰和海水蓝绿为主，用克制的毛玻璃保留地图上下文，不压暗底图。
3. **有人味**：照片、真实反馈和少量手绘细节带来温度。
4. **可信**：推荐、风险、来源与更新时间有稳定、克制的表达。

产品的核心视觉句法是：

```text
干净地图 + 少量店铺候选 + 具体商品引子 + 店铺综合判断 + 可核验来源
```

## 2. 设计原则

### 2.1 信息优先于装饰

- 每个页面只保留一个主要任务。
- 每张卡只允许一个主标题、一个核心结论和一个主要动作。
- 不用粗边框、重阴影或大量色块弥补层级不足。

### 2.2 推荐必须具体

- 优先写商品、味道、场景、时机和风险。
- 不把“必买”“网红”“隐藏神店”“高分”当作核心信息。
- 证据不足时直接说明，不用 AI 补齐情绪化文案。

### 2.3 地图保持安静

- 城市尺度不显示 Dig POI。
- 街区尺度只显示排序后的推荐候选。
- 卡片横滑不移动地图；内容浏览和空间浏览相互独立。
- 底图不叠加亮度、灰度或暗色蒙层。

### 2.4 手绘只负责“记忆点”

- 可用于收藏环、选中环、空状态、日志贴纸和少量强调图标。
- 不用于地图道路、所有按钮边框、长段文字背景或密集标记。
- 线稿统一使用粗黑或品牌深墨色，背景必须为白色或透明。

### 2.5 毛玻璃只用于空间关系

- 毛玻璃用于地图上的 sheet 外壳、浮动工具条和少量控制按钮，让用户仍能感知背后的地图。
- 正文区域保持 `84%–92%` 的不透明度，文字不能直接压在复杂地图上。
- 同一层级只出现一个主要玻璃表面，不把每个内容分组都做成玻璃卡片。
- 玻璃表面必须提供无 `backdrop-filter` 时的高不透明降级方案。

## 3. 视觉基础

### 3.1 颜色

| 角色 | Token | 色值 | 用法 |
| --- | --- | --- | --- |
| 页面背景 | `bg` | `#F3F7F8` | 非地图页面底色、空白区 |
| 主表面 | `surface` | `#FFFFFF` | 卡片、面板、浮层 |
| 次表面 | `surface-2` | `#EAF1F3` | 次按钮、信息分组、占位 |
| 主文字 | `text` | `#18323A` | 标题、关键结论 |
| 次文字 | `text-2` | `#506A73` | 正文、解释 |
| 辅助文字 | `text-3` | `#6D838B` | 时间、来源、提示 |
| 品牌强调 | `accent` | `#16778D` | 主按钮、Top 推荐、链接 |
| 强调浅底 | `accent-soft` | `#DDF1F3` | 选中项、轻提示 |
| 成功 | `success` | `#287565` | 营业、已验证到店 |
| 警示 | `warning` | `#C27B24` | 排队、售罄、预约风险 |
| 危险 | `danger` | `#B7594E` | 闭店、明确异常 |
| 收藏 | `saved` | `#D6A12A` | 收藏环和到店提醒 |
| 玻璃主表面 | `glass-surface` | `rgba(247,251,252,.84)` | 地图 sheet 外壳 |
| 玻璃控件 | `glass-control` | `rgba(255,255,255,.62)` | 次要动作与状态胶囊 |

规则：

- 任何单屏中，高饱和状态色不超过三种。
- 品类不使用一套彩虹颜色；品类主要通过文字和图标识别。
- 正文不得使用纯黑，地图也不得用半透明黑层压暗。
- 警示色只表达风险，不用于普通推荐。

### 3.2 字体

统一字体栈：

```css
-apple-system, BlinkMacSystemFont, "SF Pro Text", "PingFang HK",
"PingFang TC", "Noto Sans HK", "Microsoft JhengHei", sans-serif
```

禁止：

- 中文使用宋体或衬线体作为正文。
- 中英文混排时英文单独切换装饰字体。
- 用全大写英文制造标签感。

字号层级：

| 层级 | 字号 / 行高 | 字重 | 场景 |
| --- | --- | --- | --- |
| Display | 24 / 30 | 700 | 重点页面主标题 |
| H1 | 19 / 25 | 700 | 店铺详情标题 |
| H2 | 16 / 22 | 700 | 内容分区标题 |
| Card title | 13 / 18 | 700 | 地图横滑卡核心判断 |
| Body | 14 / 24 | 400–500 | 解释与总结 |
| Supporting | 12 / 18 | 500–600 | 风险、来源、按钮 |
| Meta | 10–11 / 15 | 500–600 | 时间、距离、更新状态 |

### 3.3 间距

使用 4px 基础网格：`4 / 8 / 12 / 16 / 20 / 24 / 32`。

- 页面水平安全边距：20px；地图浮层可使用 16px。
- 卡片内边距：12–16px。
- 相关信息间距：4–8px。
- 分组间距：16–24px。
- 内容段落行长以手机屏一行 16–22 个汉字为宜。

### 3.4 圆角与阴影

| 组件 | 圆角 | 阴影 |
| --- | ---: | --- |
| 小控件 | 10px | 无或极轻 |
| 卡片 | 16px | `0 3px 8px rgba(24,50,58,.14)` |
| 底部面板 | 顶部 20px | `0 -6px 18px rgba(24,50,58,.16)` |
| 胶囊筛选 | 全圆角 | `0 2px 7px rgba(24,50,58,.10)` |
| 地图标签 | 10px | `0 2px 7px rgba(24,50,58,.16)` |

规则：

- 不给所有容器都加边框和阴影。
- 不使用 24px 以上圆角做普通卡片。
- 不使用粗黑描边作为默认组件语言。

### 3.5 图标

- 使用 Lucide 线性图标，默认 1.8–2.2px 线宽。
- 常规控件 16–18px，重要空状态 22–28px。
- 图标不能代替不熟悉的业务含义；风险和收藏需有可访问名称。
- 手绘图标只用于品牌性状态，不与 Lucide 在同一小组件中混用。

## 4. 页面骨架

### 4.1 顶部区

- 高度以 80px 为基准，包含安全区。
- 左侧只保留品牌或页面标题；右侧最多两个动作。
- 地图页使用白色浮动按钮，非地图页使用页面表面内的工具栏。

### 4.2 底部导航

- 一级入口固定为漫游、搜索、日志。
- 当前项使用品牌色文字和图标，不增加大色块。
- 设置放在日志的二级入口，不占用主导航。

### 4.3 Bottom Sheet

- 地图页只使用一个店铺决策 sheet，高度控制在 `54–58dvh`。
- 不再设置独立 SKU 半屏和第二层全尺寸店铺详情；一次展开必须完成主要判断。
- 顶部拖拽条只是提示，不作为唯一操作方式。
- 下滑关闭和明确关闭按钮必须得到相同结果。
- sheet 内部纵向滚动，地图始终在上方保留空间上下文。

## 5. 地图语言

### 5.1 缩放层级

| 缩放层 | Dig 信息 | 标签策略 |
| --- | --- | --- |
| 城市 `< 13.8` | 不显示 Dig POI | 无 |
| 街区 `13.8–15.4` | 最多 8 个排序结果；Top 3 主标记，其余小点 | 默认无标签，选中项例外 |
| 街道 `15.4–16.3` | 最多 10 个排序结果 | Top 5 尝试显示店名与步行时间 |
| 细节 `≥ 16.3` | 保留 10 个结果 | 碰撞允许时补充决定性理由 |

### 5.2 标记优先级

优先级从高到低：

1. 用户当前选中。
2. 收藏且状态可用。
3. Top 3 推荐。
4. 第 4–5 名推荐。
5. 其他有证据候选。

标签碰撞时，低优先级退化为点，不允许互相覆盖文字。

### 5.3 地图交互

- 拖图只改变视角，不触发自动请求或推荐重排。
- 横滑店铺卡不移动地图。
- 点击 POI 或店铺卡打开半屏店铺详情，但不自动缩放或重新居中。
- “回到我的位置”是唯一明确改变到用户位置的动作。
- 不提供“搜索此区域”悬浮按钮。

## 6. 卡片语言

### 6.1 紧凑店铺比较卡

信息顺序：

1. 店面门头或最具识别度的照片。
2. 店名与步行时间。
3. AI 一句话综合判断。
4. 品类与一个代表性 SKU。
5. 近期内容数量与进入箭头。

卡片尺寸控制在 `286–296px × 96–100px`。整张卡都是进入店铺详情的点击区域，不使用“看看这款”等嵌套动作。横滑卡不使用选中描边，也不与地图形成自动同步。

### 6.2 半屏店铺决策详情

首屏必须回答：

- 这是一家什么店，现在是否值得去？
- AI 综合所有来源后得出的主要判断是什么？
- 有哪些代表性商品，而不是只强调一个 SKU？
- 什么时候去更合适，最大风险是什么？
- 营业、付款、地址和路线信息是什么？

内容顺序：店名与状态 → 门头/餐品照片 → AI 综合判断 → 招牌集合 → 到店风险 → 实用信息 → 外部链接。照片首张优先门头，至少再提供一张餐品照片。AI 摘要必须基于该店全部有效 claim 和来源，而不是改写单个 SKU 文案。

### 6.3 信息增量规则

- 横滑卡回答“附近几家里，哪家值得先比较”。
- 半屏详情回答“这家店现在是否值得专程或顺路去”。
- 每次点击都必须增加新的判断信息，不能只换一个更大的容器重复卡片文案。
- 不建设 SKU 详情层、全屏证据层或第二个店铺详情层。

半屏详情不展示“去了怎么选”“去过的人留下了什么”或“资料来源”标题。外部来源以可识别的链接按钮直接呈现。

### 6.4 动作层级

- 横滑卡：整张卡为单一进入动作，不添加卡内按钮。
- 半屏店铺详情：主动作是“开始步行”；收藏和打卡只使用图标次动作。
- 关闭按钮和向下滑动都退出 sheet，不设置阶段切换。
- 同一个动作不能同时出现在头部、正文和底部工具条。

## 7. 内容与 UI 文案

### 7.1 语气

语气像熟悉当地的朋友：具体、克制、愿意说明不确定性。

推荐：

- “脆壳和焦糖边，是近期最一致的反馈。”
- “下午三点后，热门品项不一定齐。”
- “更适合买走边逛，不必为了堂食排队。”

避免：

- “必买：酸种蛋挞”
- “证据：18 条”
- “主打 Chinese”
- “高分宝藏店”
- “AI 为你精选”

### 7.2 状态表达

| 数据状态 | 文案 |
| --- | --- |
| 已核验营业 | 现在营业 |
| 已核验休息 | 现在休息 |
| 状态未知 | 营业状态待核验 |
| 证据不足 | 资料仍在累积 |
| 有短期风险 | 到店前留意 |
| 用户真实到店 | 已验证到店 |

不要把置信度写成生硬百分比；必要时使用“共识较强 / 仍有分歧 / 资料不足”。

## 8. 动效

- 快速反馈：120ms。
- 面板和状态切换：200ms。
- 地图明确定位：360–500ms。
- 默认缓动：`cubic-bezier(0.22, 1, 0.36, 1)`。
- 动效只说明空间关系或状态变化，不持续漂浮、闪烁或弹跳。
- 遵守 `prefers-reduced-motion`。

## 9. 可访问性

- 所有可点击区域最小 44×44px；横滑卡整体可点击。
- 正文与白色背景对比度达到 WCAG AA。
- 不能只靠颜色表达营业、风险或收藏状态。
- 图标按钮必须提供 `aria-label`。
- Bottom Sheet 必须有可点击的关闭动作，并支持明确的下滑退出反馈。
- 图片需要描述内容的 `alt`，来源标识不写进 `alt`。

## 10. 组件一致性清单

新建或修改组件前必须检查：

- [ ] 是否使用规范颜色，而不是新增近似色。
- [ ] 是否遵循 4px 间距网格。
- [ ] 是否只保留一个主要动作。
- [ ] 是否避免粗边框、重阴影和过大圆角。
- [ ] 中文是否使用无衬线字体。
- [ ] 推荐文案是否具体到 SKU、场景、时机或风险。
- [ ] 证据不足时是否停止生成推荐结论。
- [ ] 手绘元素是否只承担强调作用。
- [ ] 地图交互是否保持镜头稳定。
- [ ] 44px 点击区、对比度和可访问名称是否合格。

## 11. 代码映射

当前全局实现位于 `src/index.css`：

- Tailwind 主题色：`--color-*` 与 `--color-app-*`。
- 间距：`--dig-space-1` 至 `--dig-space-6`。
- 圆角：`--dig-radius-control`、`--dig-radius-card`、`--dig-radius-sheet`。
- 阴影：`--dig-shadow-float`、`--dig-shadow-sheet`。
- 动效：`--dig-duration-fast`、`--dig-duration-base`、`--dig-ease-out`。
- 状态：`--dig-success`、`--dig-warning`、`--dig-danger`。
- 毛玻璃：`--dig-glass-surface`、`--dig-glass-control`、`--dig-glass-line`。
- 玻璃组件类：`.dig-glass-sheet`、`.dig-glass-bar`、`.dig-glass-control`。

新增组件应优先复用这些 token；需要新增 token 时，先说明它解决了哪一种现有 token 无法表达的语义。
