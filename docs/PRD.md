# Dig 产品需求文档

版本：v0.7 · 更新日期：2026-09-23 · 状态：本地面试 demo 迭代中，待视觉验收

## 1. 产品定位

Dig 是面向街头探索者的移动优先工具，帮助用户根据附近店铺的简短总结和结构化事实，快速判断一家店是否值得走进去。当前项目以香港街区为主要场景。

“3 秒决定是否进店”是产品体验目标，尚未经过可用性测试验证。

## 2. 已确认的需求与优先级

以下内容由产品负责人在本次讨论中明确提出。

| 优先级 | 需求 | 对产品设计的要求 |
| --- | --- | --- |
| P0 | 给出判断价值 | 用户应能快速理解店铺为什么值得去，而不只是看到名称和类别。 |
| P1 | 告诉用户附近有什么 | 提供附近店铺发现能力，但信息展示应优先服务选择与判断。 |

地图上的 POI 需要能够直接提供店铺总结。这是核心意图；是否每个 POI 同时展开、总结长度及展示层级尚未定稿。

视觉期望：温暖、有人情味的日系或北欧风格，尤其改善地图的美感与趣味性，参考“小红书打卡地图”的表达方式。尚未提供具体参考图片。

## 3. 当前问题

### 3.1 POI 信息拥挤

店铺总结导致标签较长、信息密度较高。接入全量 POI 后存在堆叠风险，影响地图阅读和店铺判断。全量数据下的实际重叠率、标签数量及性能尚未测量。

核心矛盾：保留直接可见的判断信息，同时避免所有店铺以同等视觉权重占满地图。

### 3.2 视觉体验不符合期望

当前页面风格缺乏期望中的温暖感和人情味；地图观感不够美观、有趣，未形成打卡地图的体验。

技术核对：当前 `src/components/map/MapContainer.tsx` 使用 Pigeon Maps 和 Carto Positron 栅格瓦片。地点数据与底图样式应分别看待；项目说明中提及 Google Maps，但不代表当前该组件使用 Google Maps。栅格瓦片不便逐项调整道路、建筑、地名等样式，后续需要评估底图方案。

## 4. 建议方案（待验证，未作为已批准实现）

### 4.1 分层展示 POI

| 层级 | 建议表现 | 目的 |
| --- | --- | --- |
| 重点店铺 | 当前视野内少量店铺展示短判断标签 | 直接传递选择价值 |
| 其他店铺 | 保留小图标，放大或点选后展开 | 保留附近发现能力，减少拥挤 |
| 选中店铺 | 底部轻量卡片展示完整判断和事实 | 承接标签放不下的细节 |

短标签示例：“一人也坐得住”“现烤肉桂卷”。这些只是文案方向示例，并非对真实店铺的事实陈述。避免仅用“精品咖啡”等类别描述替代判断价值。

建议按屏幕空间、缩放级别和碰撞情况控制标签，并保持拖动时展示稳定。重点店铺的选择规则、最大标签数量、标签长度和切换机制待确定。

卡片建议回答：为什么值得去、适合什么场景、有什么需要注意。判断应有可追溯的信息依据；未知信息不应生成确定性结论。具体来源、时效及可信度展示方式待确定。

### 4.2 视觉方向

建议采用北欧的简洁底色与日系街区手帐感，最终组合尚待视觉验证。

| 元素 | 建议方向 |
| --- | --- |
| 底图 | 暖米白陆地、浅灰褐道路、鼠尾草绿公园、淡蓝水面，弱化无关地名 |
| POI | 轻手绘感的品类图标与纸签式短总结 |
| 页面 | 奶油白、可可棕为主，少量陶土橘和柔和绿色 |
| 字体与卡片 | 清晰温和、柔和圆角与轻阴影，减少技术感和全大写标签 |
| 个人记录 | 收藏贴纸、到访印章等表达个人足迹，具体范围待定 |

打卡地图的趣味性应与真实街道可读性兼容，不能影响定位店铺。底图供应商、渲染技术、成本与授权要求尚未选定。

## 5. 建议的下一轮验证范围

以西营盘一个高密度街区作为试验区域，同时验证底图、POI 分层标签和底部判断卡。该范围是讨论中提出的建议，并非已确认排期。

建议验证：

- 密集 POI 下，重点标签可读、不相互遮挡，其他店铺仍可发现和点选。
- 缩放和拖动时标签切换稳定，选中状态清晰。
- 用户能从标签或卡片说出店铺值得去的原因，而不仅是类别。
- 在移动端约 430px 宽及更窄屏幕上，地图和判断信息仍可操作。
- 风格符合温暖、有人情味和打卡地图的期待，街道保持可读。

这些是建议验收维度；量化阈值、测试数据规模和最终验收方式待确定。

## 8. 第一轮实现记录（2026-09-12）

状态：本轮实现已被产品负责人否决并回滚。以下仅保留历史记录，不代表当前代码。用户已授权开始修改；下述参数是实现选择，未视为最终产品规格。

- 用暖米白、可可棕及低饱和品类色替换主要界面色彩；首页采用街区手帐式标题、纸签标记与浮动导航。
- 标签使用固定 148 × 72px 纸签，展示店名与一行短总结，过长内容省略；完整理由通过点选后的判断卡和详情查看。
- 视野内按可用面积最多展示 8 个重点标签，低于 15 级缩放不主动展示总结。排序先考虑选中状态，再考虑总结及理由是否存在，最后用稳定 ID 排序；这只是资料完整度规则，不代表店铺质量评分。
- 标签保留与顶部操作区、底部卡片的空间，执行碰撞检测。不具备总结的店铺继续保留，不再静默隐藏。
- 其他 POI 以 52px 世界像素网格归组，展示数量；点选数量打开店铺列表，即使最高缩放或完全同坐标也可访问各店铺。
- 点选店铺先显示底部判断卡，进一步操作打开原有详情。移除首页对详情卡的重复弹层包装。
- 恢复地图来源标注，增加放大、缩小、返回位置及刷新入口的可访问名称。
- 本轮保留 Carto 栅格底图，通过仅作用于瓦片的暖色滤镜调整观感。尚未实现可逐层设计的矢量底图、插画地标或个人打卡贴纸；这些仍属后续迭代。

## 11. 清新食欲视觉与店铺实拍（2026-09-23）

### 本轮需求

用户提出：进一步考虑配色和字体，让人感到清新、有食欲；增加 collage 和透明毛玻璃感；搜索页、榜单列表图标应附真实店铺图片。

### 设计与实现

- 清透白为主、薄荷绿与浅蓝为环境色；小面积奶油黄、烘焙橙用于食物贴纸和排名，食物本身保留真实颜色。不恢复此前被否决的棕米色地图。
- 中文采用系统苹方，正文采用 Apple 系统字体，标题优先使用系统圆体。避免外部字体加载阻塞；店名约 15px、搜索输入 16px，判断摘要与辅助信息明确分层。
- 搜索页加入可读的两行标题、可颂贴纸、半透明胶带、真实照片白边和错位衬纸。拼贴仅作为视觉层，不改变搜索、分类与详情跳转逻辑。
- 搜索页顶栏、底部导航、半屏榜单使用半透明白与背景模糊；正文保持深色。不支持 backdrop-filter 的浏览器使用实色底板。
- 搜索与榜单共用 ShopPhoto：店铺实拍为主图，菜系 emoji 为右下角角标；固定图片尺寸、延迟加载、加载失败提示，避免布局跳动与破图。
- 详情页展示对应照片及可点击摄影/来源链接；资料图片不表示当前装修、菜品供应或营业状态。
- 开屏同步白、薄荷绿、浅蓝与玻璃咖啡圆盘；继续支持跳过和减少动态效果。日志的原有资料、统计和双 tab 结构不变。

## 12. 漫游玻璃底座与日志独立入口（2026-09-23）

本节按用户最新要求更新信息架构，替代 v0.4–v0.5 中 demo 日志必须保留内嵌双 tab 的约束；旧版本记录作为历史保留。原实时模式不变。

### 视觉

- 漫游页底部店铺分类栏改为悬浮圆角毛玻璃底座，左右与下方留出地图间隙，使用半透明浅绿/浅蓝、20px 背景模糊、细白边与柔和阴影，取消实白渐变遮罩。
- 仅装饰高光做缓慢透明度变化，分类栏位置和图标不移动；系统减少动态效果偏好下停止呼吸动画。
- 调整图标可见范围、地图工具和来源标注位置，避开玻璃底座覆盖区。分类数量和点击榜单逻辑保留。
- dig 使用本地 SVG 定制圆润字标，绿色叶片作为 i 的点；首页、开屏及桌面展示统一使用，不依赖远程字体。

### 信息架构
